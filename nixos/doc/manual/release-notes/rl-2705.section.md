## Backward Incompatibilities {#sec-release-27.05-incompatibilities}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- The `boot.loader.refind` module and the `refind` package have been removed because upstream rEFInd was unmaintained.

- [](#opt-services.mealie.settings) has a proper type now:
  - Booleans are coerced to `"true"` and `"false"` instead of `"1"` and `""`.
  - Values other than booleans, ints, strings, paths or packages will be rejected.
  - `null` values now unset the value instead of producing an empty string.

- The `services.mautrix-*` bridge modules (`mautrix-discord`, `mautrix-meta`, `mautrix-signal`,
  `mautrix-telegram`, and `mautrix-whatsapp`) now share a common configuration helper under
  `nixos/modules/services/matrix/mautrix/`. All bridges now expose normalized options
  (`dataDir`, `environmentFiles`, `serviceDependencies`, `registerToSynapse`, `rateLimited`,
  `registrationFile`, `serviceUnit`, and `registrationServiceUnit`), generate their registration
  in a dedicated unit ordered before Synapse startup, and share secret substitution
  (`$VAR`, `${VAR}`, `$$` escaping, `json::` values, and
  `MAUTRIX_<BRIDGE>_BRIDGE_LOGIN_SHARED_SECRET` / `MAUTRIX_BRIDGE_LOGIN_SHARED_SECRET`).
  - `environmentFile` is deprecated in favor of `environmentFiles` (existing configs continue to work with a warning).
  - Secret substitution now fails if a referenced `$VAR` or `${VAR}` environment variable is unset (previously `envsubst` replaced unset variables with an empty string), and `$$` now expands to a literal `$`.
  - Application-service registrations now have `rate_limited = false` by default, configurable via `rateLimited`, and bridge services run with `UMask = "0077"` (runtime `config.yaml` and databases are no longer group-readable; only the registration file remains `0640`).
  - For all bridges (including `services.mautrix-discord`), `settings.appservice.address` now defaults to a literal loopback IP (`http://127.0.0.1:<port>`) instead of `localhost`, and `services.mautrix-meta` / `services.mautrix-telegram` now bind `127.0.0.1` instead of `localhost` by default.
  - For `services.mautrix-signal` and `services.mautrix-whatsapp`, `settings.homeserver.address` no longer defaults to `http://localhost:8448`; it is auto-detected from a local Synapse or Conduit service and must otherwise be set explicitly.
  - For `services.mautrix-signal`, SQLite databases now use `sqlite3-fk-wal` by default (enabling WAL mode and foreign key enforcement).
  - For `services.mautrix-meta`, each instance now runs with its own group (`mautrix-meta-<name>`) instead of the shared `mautrix-meta` group, and `dataDir` now defaults to an absolute path (`/var/lib/mautrix-meta-<name>`, with relative paths deprecated).
  - For `services.mautrix-telegram`, the package was updated to the Go rewrite (`26.10`): the old Python configuration schema (`telegram`, `relaybot`, string `appservice.database`) is incompatible with the Go `bridgev2` schema (for example, MTProto credentials moved from `telegram` to `network`, so update environment variables to `MAUTRIX_TELEGRAM_NETWORK__API_ID` and `MAUTRIX_TELEGRAM_NETWORK__API_HASH`, or reference custom variables in `settings.network`). Upstream removed legacy Python database migration in `v26.10`: upgrading directly from `0.15.3` is not supported, so either migrate first using an intermediate Go release (`v26.04`–`v26.09`) or back up and move `/var/lib/mautrix-telegram/mautrix-telegram.db` (or your PostgreSQL database) to start fresh.

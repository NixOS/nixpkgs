## Backward Incompatibilities {#sec-release-27.05-incompatibilities}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- The `boot.loader.refind` module and the `refind` package have been removed because upstream rEFInd was unmaintained.

- [](#opt-services.mealie.settings) has a proper type now:
  - Booleans are coerced to `"true"` and `"false"` instead of `"1"` and `""`.
  - Values other than booleans, ints, strings, paths or packages will be rejected.
  - `null` values now unset the value instead of producing an empty string.

## Other Notable Changes {#sec-release-27.05-notable-changes}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- [`programs.ccache`](#opt-programs.ccache.enable) is polished up a little.
  - When `programs.ccache.enable` is true, the configured cache directory is added to [](#opt-nix.settings.extra-sandbox-paths) for you.
    An `/etc/ccache.conf` is also added to the sandbox, meaning that any use of `ccache` inside the build sandbox will use the configured cache.
    (Previously, `pkgs.ccacheWrapper` had to be configured with an overlay if you wanted to use the same cache in a project separate from your NixOS configuration.
    If Nix is configured not to use sandboxing, this remains the case.)
  - The cache settings are configurable via [](#opt-programs.ccache.settings).
    These settings are linked into the cache directory, so any `ccache` configured to use the same cache directory will use these settings.
    In particular, per the previous bullet, any use of `ccache` inside the build sandbox will use these settings.
    If Nix is configured not to use sandboxing, setting `CCACHE_DIR` in `pkgs.ccacheWrapper`'s `extraConfig` is all you need now.

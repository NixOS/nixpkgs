## Other Notable Changes {#sec-release-27.05-notable-changes}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- `rocmPackages.rocm-bandwidth-test` has been removed; upstream retired it.

- `rocmPackages` has been updated from ROCm 7.2.4 to ROCm 10.1. AMD skipped
  the 8.x and 9.x series. ROCm 10 breaks ABI and API:
  `amdsmi` moves to the 27.0.0 ABI (`libamd_smi.so.27`, several clock/throttle
  APIs removed), `rocsparse` drops `rocsparse_indextype_u16`, `hipcub` removes
  its deprecated iterators and operators, and `miopen` drops its OpenCL backend.
  Update out-of-tree packages that compile against `rocmPackages` for these
  changes. The ROCm LLVM toolchain is now LLVM 24.

  `rocmPackages.rocmlir` has been removed: `ROCm/rocMLIR` has no ROCm 10
  release. MIGraphX uses `rocmPackages.rocmlir-triton`, the fork that
  AMDMIGraphX 10.1 pins. MIOpen 10.1 is built without MLIR, following
  upstream's new default.

  `rocmPackages.hipfile` is new: hipFile, ROCm's direct-to-GPU file I/O
  library (the counterpart of cuFile). PyTorch 2.14 requires it with ROCm 7.14
  and later, so `torch` with `rocmSupport` now builds against it.

  `composable_kernel`, the `miopen` CK solvers, and `vllm` no longer support
  `gfx900`/`gfx906` (Vega / MI25 / MI50 / Radeon VII) on ROCm 10.
  `rocblas`/`hipblas`-only consumers such as `llama-cpp` and `ollama` still
  build for those targets. To stay on ROCm 7.2.x, use the NixOS 26.11
  stable channel.

  The versioned `rocmPackages_10` attribute remains available. MIOpen's hipconv
  backend is disabled because its cdna4 kernels fail to compile with the ROCm
  LLVM 24 toolchain.

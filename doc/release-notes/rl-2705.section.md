## Backward Incompatibilities {#sec-nixpkgs-release-27.05-incompatibilities}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- `mangohud` now names its Vulkan layers as upstream does, `VK_LAYER_MANGOHUD_overlay_x86_64` and `VK_LAYER_MANGOHUD_overlay_x86`, instead of `VK_LAYER_MANGOHUD_overlay_64_x86_64` and `VK_LAYER_MANGOHUD_overlay_32_x86`.
  Configurations that name these layers in `VK_INSTANCE_LAYERS`, `VK_LOADER_LAYERS_ENABLE`, `VK_LOADER_LAYERS_DISABLE` or a Vulkan loader settings file need the new names.

- `modsecurity-crs` has been updated from 3.3.4 to 4.31.0.
  - `crs-setup.conf` variables were added, renamed, and removed; recreate it from `share/modsecurity-crs/crs-setup.conf.example`.
  - Rule IDs and paranoia levels changed; review custom exclusions such as `SecRuleRemoveById`.
  - The application-specific exclusion rules (`REQUEST-903.*`, e.g. for WordPress or Nextcloud) have been replaced by CRS plugins, which `modsecurity-crs.load.example` now loads from `/etc/modsecurity/crs/plugins/`.

  See the [upstream migration guide](https://coreruleset.org/20260330/migrating-crs-3-to-4-part-1-overview/) for details.

## Backward Incompatibilities {#sec-nixpkgs-release-27.05-incompatibilities}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- `nvtopPackages` has been replaced by a single `nvtop` package that supports all GPU families.
  `nvtopPackages.full` and the per-family variants are now deprecated aliases of `nvtop`.
  Use `nvtop.override` to disable the GPU families you don't need, for example `nvtop.override { nvidia = false; }`.
  The `cudaSupport` and `cudaPackages` arguments have been removed, as CUDA is no longer needed at build time.

- `mangohud` now names its Vulkan layers as upstream does, `VK_LAYER_MANGOHUD_overlay_x86_64` and `VK_LAYER_MANGOHUD_overlay_x86`, instead of `VK_LAYER_MANGOHUD_overlay_64_x86_64` and `VK_LAYER_MANGOHUD_overlay_32_x86`.
  Configurations that name these layers in `VK_INSTANCE_LAYERS`, `VK_LOADER_LAYERS_ENABLE`, `VK_LOADER_LAYERS_DISABLE` or a Vulkan loader settings file need the new names.

- `nitrotpm-tools` has been updated from 1.1.2 to 2.0.0, which contains several breaking changes:
  - `nitro-tpm-attest` now needs the kernel resource manager `/dev/tpmrm0`, and `TPM_RESOURCE_MANAGER_DEVICE` sets its path.
  - On kernels before 6.3, `nitro-tpm-attest` also needs `/dev/tpm0`, and `TPM_DEVICE` now only sets the path of this device.
  - `nitro-tpm-attest` now exits with 75 instead of 1 on temporary failures, such as too little NV memory.

  See the [upstream changelog](https://github.com/aws/NitroTPM-Tools/blob/v2.0.0/CHANGELOG.md) for details.

- `suitesparse` no longer builds GraphBLAS, LAGraph and Mongoose. Use `suitesparse-graphblas`, `suitesparse-lagraph` and `mongoose` instead.

- `sherpa-onnx` has been updated to 2.0, which no longer embeds espeak-ng and piper-phonemize. Text-to-speech callers that relied on piper models have to phonemize outside the library and pass `phoneme_codepoints` or `tokens` instead of `text`.

## Other Notable Changes {#sec-nixpkgs-release-27.05-notable-changes}

<!-- To avoid merge conflicts, consider adding your item at an arbitrary place in the list instead. -->

- `godot-mono` now supports using a dotnet version other than the one it was built with. To do so, override `useDotnetFromEnv` to `true` in the package and add your desired dotnet version (or versions using `dotnetCorePackages.combinePackages`) to your build time environment, e.g. in `stdenv.mkDerivation`'s `nativeBuildInputs`.
